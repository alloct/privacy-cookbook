# Architecture

## Summary

The Privacy Cookbook is a fully static site generated by
[Eleventy](https://www.11ty.dev/) (11ty) v3, with client-side search provided
by [Pagefind](https://pagefind.app/). The production output is plain HTML,
CSS, two small first-party scripts, and a static search index — no backend,
no database, no runtime services, no third-party requests.

## Framework evaluation

Requirements: GitHub Pages compatibility, Markdown-first content, scalable
navigation, local search, accessibility, low client-side JavaScript, small
supply chain, contributor friendliness, reproducible builds.

Candidates considered:

| Option | Verdict | Reasoning |
| --- | --- | --- |
| **Eleventy + Pagefind** | **Selected** | Zero client JS by default; output is exactly what we write; tiny dependency tree (5 direct dev dependencies); templates are plain Nunjucks + CSS we fully control; Node is a mainstream contributor toolchain; Pagefind provides static, self-hosted, chunked search that scales to thousands of pages. |
| MkDocs Material | Rejected | Excellent docs framework, but it is what Privacy Guides uses — adopting it would make this site a visual near-clone, against the project's originality requirement. It also ships more bundled JS than we need and theming deeply means fighting the theme. |
| Hugo | Rejected | Single-binary speed is attractive, but Go templating raises the contributor bar, and we'd still build all theme/search/a11y work ourselves without npm's ecosystem for the few tools we do want. |
| Zola | Rejected | Same tradeoffs as Hugo with a smaller ecosystem and fewer maintainers. |
| Astro (Starlight) | Rejected | Good accessibility and search out of the box, but a much larger dependency tree and a component/framework mental model that contradicts "adding content must not require touching application code." |
| Jekyll | Rejected | Native to GitHub Pages but effectively in maintenance mode; the Ruby toolchain is a persistent friction point, especially on Windows. |

Decision criteria that dominated: **supply-chain size** (every dependency is
attack surface for a security-focused project), **originality of design**
(we own every line of CSS), and **JS minimalism** (search is the only
feature that requires client-side JavaScript, and it's confined to one
page).

## How the pieces fit

```
src/                      content + templates (input)
├── _data/                site.js (metadata), nav.json (navigation tree)
├── _includes/
│   ├── layouts/          base.njk, article.njk, section.njk
│   └── partials/         head, header, sidebar, footer
├── assets/               css, js, img — copied through verbatim
├── <section>/            one directory per content section
│   ├── <section>.11tydata.json   sets layout + section name for the dir
│   ├── index.md          section landing page (layout: section.njk)
│   └── *.md              articles
├── index.njk             home page
├── search/index.njk      search page (loads Pagefind UI)
├── 404.njk, robots.njk, sitemap.njk
docs/internal/            this documentation (not built into the site)
scripts/                  validation + asset tooling
.github/workflows/        CI and deployment
_site/                    build output (gitignored)
```

Build pipeline: `eleventy` renders Markdown through Nunjucks layouts into
`_site/`, then `pagefind --site _site` crawls the rendered HTML (only
elements inside `data-pagefind-body`) and writes a static search index into
`_site/pagefind/`.

## Key design decisions

- **Navigation is data** (`src/_data/nav.json`), not code. Adding pages and
  sections never touches templates. See `navigation.md`.
- **Directory data files** give every file in a section its layout and
  section label automatically; article frontmatter stays minimal.
- **Path prefix** is environment-driven (`PATH_PREFIX`) via Eleventy's
  `HtmlBasePlugin`, so local dev serves at `/` while GitHub Pages serves at
  `/privacy-cookbook/` with no template changes.
- **All assets are first-party.** System font stacks (no webfonts), local
  images, local scripts. The CSP meta tag (`default-src 'self'`) enforces
  this at the browser level and would loudly break anything that regresses
  it.
- **JavaScript budget:** `theme.js` (~1 KB, theme toggle) on every page;
  Pagefind's UI on the search page only. Everything else works with JS
  disabled.

## Content model

Articles are Markdown with YAML frontmatter (`title`, `description`,
`tags`, `status`, `last_reviewed`; see `content-guide.md` for the full
schema and lifecycle). Callouts use `::: note` / `tip` / `warning` /
`danger` container syntax. Footnotes use standard `[^ref]` markdown-it
syntax and render as a sources section.
